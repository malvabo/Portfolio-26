Compliance certification: extracting trust from trade documents

A validation flow inside the Compliance Agent that turns a dropped certificate into structured, checked compliance data — so exporters catch a bad document before customs does.

Role

Lead Product Designer

Timeline

6 weeks

Team

PM, 2 engineers, trade-compliance SME

Product

Compliance Agent

TLDR

  • •Problem: Export teams hand-check certificates against customs rules — slow, inconsistent, and the errors surface only after a declaration is rejected.
  • •Move: Designed a drop → configure → extract flow that pulls structured fields from any certificate and grades each one by confidence.
  • •Key idea: Sort every document into three tiers — Auto-Validated, Needs review, Flagged — so people spend attention only where the agent is unsure.
  • •Result: Certification became a triage screen, not a manual read: expiry, issuer, and critical-field checks run before a human looks.

Challenge

Certificates fail quietly, then loudly

Cross-border shipments move on paper: certificates of origin, EUR.1 movement certificates, phytosanitary certificates, ISO and Rainforest Alliance certs. Each has to be consistent and current before it reaches an authority.

The business context: a single rejected declaration stalls a shipment, ties up working capital, and can mean an expired certificate no one caught in time. The user pain: compliance officers re-typed the same fields into forms and eyeballed dates and issuers by hand — accurate on a good day, unreliable at volume.

The constraint: certificates come in every layout imaginable. The system couldn't assume a fixed template — it had to adapt to whatever document was dropped in.

Process

Designing for the officer, not the happy path

I walked through real submissions with a trade-compliance SME and mapped where checks actually broke down. The pattern: extraction was never the hard part — trusting the extraction was.

Finding: blind automation erodes trust fast

An early concept just auto-filled the form. Officers didn't believe it — and one silent wrong field was worse than no automation, because it hid the error instead of surfacing it.

Decision: show confidence, not just answers

I reframed extraction around confidence per field. High-confidence values read as calm and green; anything the agent is unsure of is highlighted amber and asks for a one-click confirm.

Iteration: from a flat form to a triage verdict

Testing showed people needed a single answer to “can I trust this?” before the field detail. That became the validation tier — driven by issuer recognition, days-to-expiry, and the lowest critical-field confidence.

Solution

Drop, configure, extract — then triage

A configurable extraction schema

Instead of a fixed template, a Schema Builder lets a team define exactly which fields to pull — name, type, and a plain-language description — so the same flow handles a certificate of origin or a phytosanitary cert without rework.

Confidence you can see

Every extracted value carries a confidence score and links back to its exact span in the source document. Click a field, see where it came from. Low-confidence fields are held for a quick human confirm.

One verdict, three tiers

A validation panel resolves the whole document into a single tier, so the officer knows in a glance whether to approve, review, or escalate:

Auto-Validated

Recognized issuer, in date, critical fields high-confidence. Approve and move on.

Needs review

Expiring soon or a low-confidence critical field. A person confirms before submission.

Flagged · Non-Compliant

Unrecognized issuer or a failed check. Routed to exception escalation.

Qualitative: the confidence-first framing did the real work — officers trusted the agent because it admitted uncertainty instead of hiding it.

Product: certification slotted in as one work item beside missing-document follow-up and payment, giving the Compliance Agent a coherent triage model the whole dashboard could reuse.

Reflection

What I'd carry forward

The lesson that stuck: in an expert workflow, surfacing doubt beats projecting certainty. The design earned trust by being legibly unsure in the right places, not by pretending to be right everywhere.

What I'd do next: close the loop — feed each human confirmation back so the confidence model sharpens on the certificate types a given team actually handles.

It also sharpened how I design AI into serious workflows: make the machine's reasoning inspectable (source spans, explicit checks), and always give the human a clear place to decide.
